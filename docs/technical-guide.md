# Technical guide

Setup, data formats, testing and implementation details for AA Proteome Interaction Atlas. For the app introduction, main features and analysis settings, see the [README](../README.md). Commands below are run from the app folder, not from `docs/`.

A static web app for exploring Arabidopsis amino-acid docking results across 20 canonical amino acids, with 19 D-AA datasets kept separately for stereochemical comparisons. Glycine has no distinct L/D pair. No build step, package installation or backend is required; the optional 3D viewer loads Mol* and AlphaFold structures from external services.

## Run locally

The app reads the gzipped AA result TSV files directly over HTTP and decompresses them in the browser. Start a local web server from this folder:

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

Then open <http://127.0.0.1:8765/>. Double-clicking `index.html` is no longer supported because browsers restrict fetching local TSV files.

## GitHub Pages

Publish this folder as a GitHub Pages site, keeping `index.html`, `js/`, `css/`, `assets/`, `At_results/`, and `annotations/arabidopsis/` together. The annotation files used by the app are:

- `arabidopsis_uniprot.tsv.gz`: protein/gene identifiers, loaded at startup.
- `At_custom_description_file.csv.gz`: gene-description dialogs, loaded on demand.
- `arabidopsis_uniprot_go.tsv.gz`: GO analysis, loaded on demand.
- `strict_WT_single_protein_AA_controls.tsv`: Control QC, loaded on demand. The older `nonredundant_AA_protein_controls.tsv` is not the active control source.

The loader uses relative paths, so it also works under a repository URL such as `https://USERNAME.github.io/REPOSITORY/`. Preserve the capitalization of `At_results` and publish each data bundle with its matching manifest, metadata and optional coordinate/electrostatics files.

If these files are at the root of your repository, use **Settings > Pages > Build and deployment > Deploy from a branch**, and select your branch and **/(root)**. See the [GitHub Pages publishing instructions](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

The browser never loads `tests/`. Keep it in the repository for regression checks; it can be omitted from a deployment-only copy. Node.js is needed only to run those checks, not to serve the app. Upstream Python pipeline scripts are also not runtime dependencies.

Before a public release, confirm redistribution permissions and attribution for the annotation/result files and document the code and data licenses. After deployment, check all nine tabs, table/plot downloads, gene-description dialogs and the Mol* overlays in a fresh browser session; local automated checks do not verify the deployed browser experience.

## Browser requirements and loading

Use an up-to-date browser with `DecompressionStream` support. Serve the app over HTTPS or localhost so checksum validation is available; do not open it through `file://`. The 3D viewer additionally needs WebGL and access to jsDelivr and AlphaFold DB.

Startup loads all available compact L/D score tables and the UniProt identifier annotations, using small batches. The progress bar measures completed loading steps, not downloaded bytes or estimated remaining time. Compressed file sizes are not memory requirements: the full proteome is expanded into JavaScript objects and rankings are cached, so initial loading and analysis can be demanding on lower-memory devices. Check performance with the full dataset on the browsers/devices you intend to support.

Gene descriptions, GO annotations, experimental controls, ligand coordinates, pocket points and electrostatics are loaded on demand. Ligand coordinates are fetched one AA file at a time; the shared pocket-point table is downloaded as a whole on first use. See the viewer sections below for cache limits and optional-data behavior.

## Regression checks

Run the existing `tests/*.test.cjs` scripts from the app folder with Node.js; no additional packages are required. They use in-memory fixtures/mocked browser interfaces and read local files without modifying the app or datasets.

PowerShell:

```powershell
Get-ChildItem tests/*.test.cjs | Sort-Object Name | ForEach-Object {
    node $_.FullName
    if ($LASTEXITCODE -ne 0) { throw "Test failed: $($_.Name)" }
}
```

Bash:

```bash
for test in tests/*.test.cjs; do
    node "$test" || exit 1
done
```

`ranking-consistency.test.cjs` covers shared QC-first ranking, GO selection, inspected-pocket comparisons, L/D filtering and model identity. Other scripts cover profile normalization, loading progress, statistics plotting, ligand poses, protein representations/colors, pocket clouds and electrostatics.

To additionally check the bundled ligand-coordinate files against the current L score/pocket tables, including the Q38933 CYS/ASP regression cases:

```sh
node tests/ligand-viewer.test.cjs --real-data
```

These checks are not live browser or visual end-to-end tests. The real-data check is specific to the supplied dataset and its named regression cases.

## Compact pipeline export (recommended)

Run the standalone Python pipeline script after collecting the **all-pocket** Vina and SFCT results. Python 3.10+ is sufficient; it uses only the standard library, with no pandas, RDKit, or other packages required. From the app folder, replace the placeholder script and source paths below with their locations in your pipeline:

```powershell
python PATH/TO/prepare_atlas_data.py --vina-dir PATH/TO/L/vina --sfct-dir PATH/TO/L/sfct --output At_results/L
python PATH/TO/prepare_atlas_data.py --vina-dir PATH/TO/D/vina --sfct-dir PATH/TO/D/sfct --output At_results/D
```

For subsequent exports into the same generated folder, add `--overwrite`. This only replaces the exporter's bundle files; it does not delete or change the original result files. A nonempty output folder without this exporter's manifest is never overwritten. The output must be separate from the input directories, not inside or above either one. Unrelated files in an existing output folder are not deleted.

Keep `prepare_atlas_data.py` in the upstream pipeline; the browser app does not need the Python script. Both input arguments may point to the same flat `results` directory if it contains both filename prefixes. Inputs may be plain `.tsv` or `.tsv.gz`; having both forms of the same input is rejected to avoid silently selecting a stale copy. Use the original all-pocket tables, **not** best-per-protein or top-hit tables. If `uniprot_id` is absent, it is extracted from the AlphaFold `protein` identifier; absent TAIR annotations are left blank rather than invented.

The generated bundle contains:

```text
At_results/
  L/
    manifest.json
    pockets.tsv.gz
    scores_ala.tsv.gz
    ...
    scores_val.tsv.gz
  D/
    manifest.json
    pockets.tsv.gz
    scores_dala.tsv.gz
    ...
    scores_dval.tsv.gz
```

`pockets.tsv.gz` stores the shared protein/pocket metadata and residue lists once per distinct metadata record. Each AA score file refers to these records by `pocket_id` and retains independent Vina affinity/status, the SFCT-selected pose's Vina score, SFCT, supplied Combined, pose index, pose count, and SFCT status. Exact source score strings are retained: **no rounding, rescoring, quality filtering, or best-pocket reduction**. Failed rows and source-specific statuses remain in the export; the app applies its existing metric-specific success rules when loading. Per-AA row order is preserved in the files; the app uses deterministic UniProt ordering for tied protein scores. Distinct metadata snapshots receive separate IDs instead of silently rounding or overwriting them.

The manifest records format version, input size, row counts, filenames, and SHA-256 hashes of the uncompressed TSVs. Gzip output is deterministic. The script validates all sources and prepares files in a temporary directory before publishing the output, with the manifest replaced last. The app validates schemas, counts and pocket references, and verifies SHA-256 where browser cryptography is available (including GitHub Pages and localhost). On ordinary insecure HTTP, checksums may be unavailable; schema/count/reference checks still apply. Publish the **complete bundle together**, not individual score files from different exports. Regenerate after any source result changes; a present compact bundle takes precedence over raw folders.

The app loads `At_results/L/manifest.json` and the optional `At_results/D/manifest.json`. Keep each configuration's manifest, pocket file and score files together in its own folder. L manifest codes are `ALA`, `MET`, etc.; D codes are `DALA`, `DMET`, etc. The pipeline exporter used for D must support all 19 D codes. Pocket IDs are local to each bundle: they are never joined across folders merely because their numbers match. Only the generated folders need publishing; original Vina/SFCT inputs stay in your pipeline/archive. Normal app files and annotations remain required. Use the appropriate full output path when running the exporter outside the app folder.

If neither split manifest exists (HTTP 404), the earlier single-bundle `At_results/manifest.json` layout is still supported. If that is also absent, the original Vina/SFCT loader is used. A D bundle without an L manifest is an error; incomplete or corrupt bundles never silently fall back to older data. A missing D bundle or missing individual D AA leaves that control unavailable without removing any L results.

Missing AA files are omitted from the manifest and remain Missing in the app, without removing proteins from other AAs. If only one scorer is available for an AA, the exporter warns and preserves the available source. It fails when neither directory contains supported inputs. If the compact manifest is absent (HTTP 404), the app falls back to loading the original Vina/SFCT folders. An invalid or incomplete compact bundle produces a clear error, not a silent fallback to potentially older data.

## Update full-size results (legacy loading)

This fallback supports the original 20-AA plus D-MET layout. Use the split compact bundles above for the full set of D-AA controls.

- Keep the SFCT gzip files in `At_results/sfct/`, named `sfct_ala_all_pockets.tsv.gz`, `sfct_arg_all_pockets.tsv.gz`, etc.
- Keep the independent Vina gzip files in `At_results/vina/`, named `vina_ala_all_pockets.tsv.gz`, `vina_arg_all_pockets.tsv.gz`, etc. Both folders currently require all 20 canonical AAs plus D-MET (42 files total).
- For MET, the app loads `At_results/vina/vina_met_all_pockets.tsv.gz` and `At_results/sfct/sfct_met_all_pockets.tsv.gz`.
- Keep the existing TSV headers. Put UniProt annotations in `annotations/arabidopsis/arabidopsis_uniprot.tsv.gz` and TAIR descriptions in `annotations/arabidopsis/At_custom_description_file.csv.gz`.
- Commit/push the updated files, wait for GitHub Pages to publish, and reload the app. Locally, simply replace the files and reload. Result requests revalidate the browser cache.
- Without a compact manifest, no JavaScript data bundle, manual decompression, or data-generation step is required. If you use compact loading, rerun the exporter after updating the full-size files. Both annotation files are decompressed in the browser; already-decoded HTTP responses are also supported.

`At_results/` contains the real Arabidopsis docking results supplied for the atlas. The loader matches the two sources by `uniprot_id` and `pocket`, checks that the protein model, P2Rank rank/probability, pocket mean pLDDT, center and residue IDs agree (allowing numerical roundoff), and keeps the union of pockets with success in either source. Duplicate pocket keys or conflicting metadata produce an explicit error instead of silently mixing results. Source files are never modified.

**Vina** throughout the app now uses `vina_<aa>_affinity` from the Vina file, normalized internally to `vina_affinity`. It is the independently selected best Vina pose score within that pocket. The SFCT file's original `sfct_vina_score` is retained separately, never substituted for missing independent Vina results. Old shared URLs with `metric=sfct_vina_score` still select the Vina option, now backed by the independent result.

**Combined 80%** is the existing supplied `vina_sfct_combined` score: `0.2 * origin_score + 0.8 * sfct_score`, with its original exported precision preserved. **Combined 50% (default)** is calculated at load time as `vina_sfct_combined_50 = 0.5 * sfct_vina_score + 0.5 * sfct_score`. The pipeline's `origin_score` is exported as `sfct_vina_score`; it is not the independent Vina minimum. No files or manifest schemas need changing. Both L and D datasets receive the new derived value.

**SFCT** and both Combined variants describe the saved pose selected upstream by Combined 80%. The app can choose a new best pocket under Combined 50%, but cannot select a new pose within that pocket without the original pose-level scores. This is retained-pose reweighting, not a rerun or independent best-50%-pose benchmark. SFCT is also not an independently selected minimum-SFCT pose. The independently optimized Vina score may describe a different pose from all three SFCT-derived values.

Combined 50% requires successful SFCT status and finite origin/SFCT values; missing inputs remain missing, never zero. Independent Vina failure does not suppress an available 50% score. All rankings, AA selectivity, L/D comparisons, GO, overlap, matrices and distributions use the chosen metric. The raw-score competitor tolerance remains 0.10 for each combined variant; this is the existing heuristic, not a newly calibrated cutoff. The profile has both raw combined values and separate combined-80%/50% percentile options. Profile/pocket tables and downloads include both weights. In machine-readable Explorer/detail-profile exports, `combined_score` remains the supplied 80% value for compatibility; `combined_50_score` is the new value.

Control QC compares four metrics: Vina, SFCT, Combined 80% and Combined 50%, including four recovery curves, tier summaries, pocket-site recovery, L/D summaries and audit/download fields. The default eligible denominator requires all four metrics; All known controls still includes missing scores without inventing ranks. Best-pocket selection is performed independently per metric. The 50% curve inherits the saved-pose selection limitation above.

Gzip decoding uses the browser's built-in [DecompressionStream API](https://developer.mozilla.org/en-US/docs/Web/API/DecompressionStream), so use an up-to-date browser. Loading runs in small batches with a progress bar. If the web server already decodes gzip, the score loader recognizes the decoded TSV and avoids decompressing it twice. Missing files, invalid gzip data, and unexpected TSV headers produce a file-specific error. Electrostatics exports have stricter compressed-byte checksum requirements; see the electrostatics section below.

## Successful and missing results

Success is checked separately for each source: `vina_status` for Vina, and `sfct_status` for SFCT/Combined, ignoring surrounding whitespace and case. If a source file supplies a generic `status`, it takes precedence only within that source. A failed SFCT row never removes an independently successful Vina score, or vice versa. A failed MET row does not remove successful LEU rows for that protein, or successful MET rows from another pocket. Proteins do not need results for all AAs or all scores to remain eligible.

Blank or non-finite scores are missing for that metric. Rankings, percentiles and score distributions use only successful finite scores. Within-protein AA rank, competitor counts, median delta and Z use only available successful canonical AAs; the UI and Explorer exports report the number of AAs contributing. Delta and competitor count are missing when there are no other AAs; Z also requires at least two other AAs with nonzero standard deviation. L/D comparisons require successful finite scores for the selected L-AA and its matching D-AA. Correlations use pairwise shared successful proteins and are missing when there is insufficient data or no variation.

Failed rows are hidden from the Explorer and pocket table; missing AAs remain listed as Missing in the protein profile table. Source TSV files are never modified. In Explorer downloads, `delta_to_median_other_available_aas` replaces `delta_to_median_other_19`, and `available_aa_count` / `available_other_aa_count` report coverage. Undefined statistics are exported as empty cells.

## AA-normalized profile Z-score

The Full 20-AA profile has an **AA-normalized Z-score** checkbox beside **Value type**, off by default. It normalizes the selected raw value (Combined 80%, Combined 50%, Vina or SFCT), independently of Explorer's Ranking score. Selecting a percentile option automatically unchecks and disables it; returning to a raw score leaves it unchecked. The plot note, tooltips and exports identify the chosen score. For each canonical AA separately, the reference is one best successful, finite-scoring pocket per protein, selected **after** the shared P2Rank/pLDDT filters. Search, proteome tier, specificity filters, all-pocket display mode and D-AA controls do not alter this reference. Shared links preserve the base value and checkbox via `profile_value` and `profile_z=1`; older `profile_value=aa_zscore` links are migrated using their original Ranking score.

`Z = (displayed score - AA-specific mean) / AA-specific population SD`. Negative values are favorable; zero marks that AA's mean, not a significance threshold. An inspected pocket is normalized against the same best-pocket reference (including its own protein's best pocket). Fewer than two reference proteins, constant scores or missing results give missing Z-scores, never zero. Hover shows the underlying score, mean, SD and reference count. Population summaries reuse the AA/metric/QC ranking cache.

The horizontal mean reference is labeled **Z = 0**. Dashed purple segments show an **actual Top 5% cutoff for each AA**: take the last score with rank-percentile ≤ 5% in its QC-passing reference (zero-based index `floor((N - 1) * 5 / 100)`), then convert it to Z with the same mean and SD. This is not a theoretical normal-distribution cutoff. Segment heights can differ between AAs; inspected pockets retain the same best-pocket reference boundary. Hover and PNG/SVG exports include these cutoffs. Existing point colors still follow rank-percentile tiers, including tie-breaking and inspected-pocket ranking, rather than treating every score tied at a boundary as the same rank.

This is a descriptive score-baseline adjustment, not a significance test, binding probability or a calibrated comparison of affinities between ligands. It is distinct from the existing within-protein **Selectivity Z**, for which positive favors the target. Explorer calculations, the raw AA profile table/download and all existing value options are unchanged.

## L/D controls

The main Explorer, protein profile, AA matrix, overlap and GO analyses keep the canonical 20-AA universe; D-AA controls never enter its ranks, medians, Z-scores or competitor counts. For targets with a loaded D dataset, Explorer's specificity panel offers **L>D** beside the Specificity filters heading and the table shows a sortable **L/D Δ**. The delta is `D score - L score`, with positive values favoring L. It uses independent best QC-passing pockets per protein and the selected metric. Both L and D must pass the same P2Rank/pLDDT thresholds; All pockets still displays this protein-level comparison. Protein profile's inspected-pocket comparison requires the same pocket/model/residue geometry in both configurations. Missing scores remain unknown; exactly tied scores do not pass the strict preference filter. Glycine has no L/D filter. Existing `lmet_preferred=1` shared links remain supported for MET; new links use `l_preferred=1`.

Compare AAs and Statistics accept all loaded L/D datasets. Statistics provides the selected AA's L/D difference distribution and score correlation, with both configurations independently passing its P2Rank/pLDDT settings. All-AA Statistics still pools only 20 canonical AAs. Explorer exports use `d_minus_l_delta` (replacing the methionine-only field) and include `d_control_aa`, `d_control_score` and `d_control_pocket`.

Control QC adds a separate **L versus D** summary for Vina, SFCT, Combined 80% and Combined 50%: L preferred, D preferred, ties, missing pairs and median D-minus-L. It follows the selected control AA set and recovery denominator, excluding glycine; percentages use evaluable pairs for each metric. Both configurations must pass the tab's QC thresholds. Best mode compares independent best pockets; Control-matched mode uses the same experimental-site-matched pocket geometry for L and D, with no fallback. The individual-control table has sortable per-metric L/D deltas; its TSV includes D scores, pockets and deltas. Neither the D controls nor L preference alters the existing L recovery curves or site-recovery calculations; experimental-site matching uses canonical L-AA pocket records only. D-AA docking is a stereochemical comparison, not a proven nonbinding control, binding probability or FDR estimate.

The compact **L>D** checkboxes in Explorer and GO are off by default and mean predicted L preference: `L score < D score`, equivalently `D score - L score > 0`, for the selected ranking metric. Missing/failed pairs and ties do not pass. Both tabs compare independent best QC-passing pockets; the same quality thresholds apply to L and D. The option is unavailable for glycine or an unloaded D dataset. GO filters only selected hits and recalculates enrichment; neither background option is restricted by L>D. The two tabs keep independent states unless Use Explorer settings is clicked. GO term/protein/background downloads record `require_l_preference` as a selection setting, with an `_ld` filename suffix when active; it does not mean that the background itself was L>D-filtered. Methods explains the score direction, pocket convention and limits of this predicted preference.

## Comparison, overlap and macro statistics

These three views have independent controls; Explorer search, tiers and specificity filters do not affect them. P2Rank and pLDDT filters are applied **before** selecting each protein’s best successful finite score for each AA. Comparison pairs require results for both selected AAs; Δ = score(Y) − score(X), so positive values favor X. Candidate-list filters do not change the pairwise overview plot.

Overlap sets rank each AA independently after QC, breaking score ties by UniProt ID. Top tiers use `100 × (rank − 1) / (N − 1) <= tier` (one protein has percentile zero), matching the atlas rank-percentile convention. Jaccard similarity is intersection divided by union. Missing or QC-failing results are explicitly labeled; being unique to a top-hit list does not establish exclusive binding. With more than two AAs, the UpSet plot shows up to 20 largest exact intersections; every observed intersection remains selectable and downloadable.

Statistics uses either one best pocket per protein × AA or all eligible pocket rows. Pooled mode includes 20 canonical AAs, not D-AA controls. Counts distinguish unique proteins, unique protein × pocket IDs, and score observations. Percentiles, top-tier cutoffs, selectivity and L/D comparisons always use independent best QC-passing pockets. Mean/SD use the selected observation unit; SD is population SD. Pearson and Spearman correlations use all finite pairs, with average ranks for ties and missing values for undefined correlations. The Statistics correlation plot draws all eligible finite pairs, without sampling or a point limit, using a canvas layer with hover details. This includes pooled and all-pocket views and L/D comparisons; overlapping observations may occupy the same position. Only the selected correlation's full point list is materialized from source records to avoid retaining duplicate full-size arrays for every variable pair. Compare AAs retains its 2,000-point display sample. Histograms and statistics use the entire eligible population. These are summaries of loaded successful results, not a pipeline failure-rate analysis.

## GO analysis

The Methods tab includes a **GO algorithms and configuration** table distinguishing fixed ORA/Fisher/BH methods from editable protein-selection, GO-aspect and FDR controls. It also documents background selection, annotation handling, count definitions, fold enrichment, P-values and display behavior.

The GO tab reads `annotations/arabidopsis/arabidopsis_uniprot_go.tsv.gz` only when opened. Required TSV headers are `Entry`, `Gene Ontology (biological process)`, `Gene Ontology (molecular function)` and `Gene Ontology (cellular component)`. Cells use UniProt's semicolon-separated `term name [GO:0000000]` format. Repeated entries and terms are merged, with one protein counted once per term. The file stays unchanged. Failed loading is confined to the GO tab and can be retried; already HTTP-decoded gzip responses are supported.

Independent controls select the target AA, proteome tier (Top 1%, 5%, 10%, and 20%–100% in 10% steps), ranking score (Combined 80%/Combined 50%/Vina/SFCT), P2Rank threshold, pLDDT threshold and Competitive AAs maximum, with an optional **L>D** checkbox beside Define the GO analysis. Defaults are ALA / Top 5% / Combined 50% / 0.7 / 90 / 19. GO aspect (default Biological process) and FDR threshold (default 0.05; greater than 0 and at most 1) sit to their right in the same desktop options row, with soft purple borders and a light background matching Explorer's Specificity filters. **Use Explorer settings** copies the protein-selection settings including L>D (Explorer All ranks maps to Top 100%) and preserves the GO background mode, aspect and FDR threshold. Selection matches Explorer's **Best pocket** mode with search and other specificity filters disabled: it first applies the quality thresholds to all successful finite-score pockets, then selects each protein's best passing pocket and ranks the QC-qualified population. Every AA used in competitor/selectivity calculations passes those same quality thresholds. The **Background** selector defaults to **Parameter-filtered**: the same quality-eligible population without tier, Competitive AAs or L>D restrictions. **Total (target AA)** includes every protein with a successful finite score for the target AA and chosen metric, ignoring P2Rank/pLDDT thresholds—not every protein in the annotation file or proteins missing that target-AA score. Both backgrounds include the selected group. The selected hits always retain their tier, quality and competitor filters regardless of background choice. Changing background recomputes counts, enrichment, P-values and BH FDR over that background’s terms. At Top 100% with unrestricted competitors and L>D off, the filtered selection equals its background (fold and P/FDR are 1); total background may still differ because of quality filtering.

For each GO aspect, tests use only selected and background proteins with at least one supplied annotation in that aspect. The selected protein list still includes unannotated proteins, and coverage makes exclusions explicit. For a term, k/n is selected hits / annotated selected proteins, and K/N is background hits / annotated background proteins. Expected hits = nK/N; fold enrichment = (k/n)/(K/N). The P-value is a one-sided Fisher exact / hypergeometric upper tail. Log-space calculation avoids underflow. Benjamini–Hochberg FDR correction includes **all background terms across all three aspects, including zero-hit terms**, before display filtering. Terms with fold >1 and FDR at or below the chosen threshold are marked enriched.

The term table shows terms with at least one selected hit and supports aspect/search/significance filters, column sorting and pagination. The FDR-only checkbox is checked and active by default, restricting the table to enriched terms at the chosen threshold. Uncheck it to inspect other terms with selected hits. Changing the threshold updates the table, chart and all-aspect enriched-term count without changing protein sets or recalculating FDR. Clicking k/n shows the corresponding proteins, with existing UniProt links, TAIR descriptions and profile arrows. The plot displays up to 12 enriched terms ranked by adjusted significance, with fold enrichment on the x-axis and a light-to-dark purple gradient encoding −log10(FDR). Darker bars mean smaller FDR. The color legend starts at −log10(the chosen FDR threshold) and ends at the largest displayed −log10(FDR), with a minimum span of 0.1 to handle tied or near-threshold values. TSV/CSV term exports include all matching rows, settings, counts, hit IDs, P/FDR and −log10(P/FDR), plus `fdr_threshold` and `enriched_at_fdr_threshold`; separate protein TSV exports cover the selected/inspected term list or the complete chosen background. All table exports record `background_mode` and include the mode in filenames. Probability strings use scientific notation when appropriate; logarithmic columns preserve extreme significance even in downstream software with limited numeric range.

Only supplied GO annotations are analyzed: no ontology ancestor expansion, evidence filtering, GO-slim conversion or external API lookup. UniProt accessions are the counting unit, not collapsed TAIR genes. Isoforms, related GO terms, annotation bias and repeated exploration limit interpretation; this is not evidence of experimentally verified amino-acid binding. Method references: [GO enrichment and background guidance](https://www.geneontology.org/docs/go-enrichment-analysis/), [one-sided Fisher exact test](https://docs.scipy.org/doc/scipy-1.17.0/reference/generated/scipy.stats.fisher_exact.html), [BH FDR correction](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.false_discovery_control.html).

The **Enriched GO terms** plot has a **Download plot** menu for self-contained SVG and 2×-resolution PNG images. Exports preserve the currently displayed terms, fold-enrichment axis, bar colors and vertical FDR legend, and include the target AA, GO aspect, metric, tier, FDR, quality thresholds and background mode. The menu is hidden when no enriched terms match the current view.

The GO selected-protein table also shows **Competitive AAs**, using Explorer's score-tolerance rule with the GO tab's target AA and ranking score: other-AA best successful score ≤ target score + tolerance (Combined 80% and 50% 0.10 each, Vina 0.25, SFCT 0.15). Counts are shown over available other canonical AAs, up to 19; missing scores, the target AA and D-AA controls are excluded. As in Explorer, other-AA scores pass the same QC thresholds before best-pocket selection; they are not tier-filtered. The Competitive AAs ≤ filter restricts selected proteins before enrichment, while leaving the chosen background unchanged. Default 19 is unrestricted; lower limits require a finite competitor count (missing comparisons are not treated as zero). It differs from Top-hit overlap's x/20 membership count. Selected/term/background protein TSV exports include `competitive_aas`, `available_other_aa_count` and `competitive_aa_tolerance`; protein and term exports also record `max_competitive_aas`.

## Protein links and gene descriptions

### Shared QC rankings and inspected pockets

Explorer, GO, Compare, Overlap, Statistics and Control QC use one QC-first ranking implementation: successful finite scores pass P2Rank/pLDDT first, then each protein contributes its best passing pocket. Protein profile and AA matrix share Explorer's quality thresholds, visibly reported in those tabs. GO/Compare/QC profile links copy the originating thresholds and preserve the selected pocket when available. GO's Total background remains explicitly unfiltered; it does not change the QC-qualified selection or its ranks. Both L and D, and every canonical AA entering a profile/selectivity calculation, pass the same quality thresholds.

Protein score ties use UniProt ID, independent of input row order. Equal-score pockets within one protein use P2Rank rank, pocket label and model identifier. Rank percentiles remain `100 * (rank - 1) / (N - 1)`, with singleton zero. Histogram colors use these same ranks, not score-only cutoffs. An inspected pocket replaces its own protein's best score in the comparison with other proteins; the best pocket therefore keeps its original percentile.

Opening a pocket preserves its row as the comparison anchor. Cross-AA and inspected L/D comparisons require the same accession, model, pocket label, normalized residue set and center (coordinate tolerance `1e-9`). Missing or mismatched geometry is unknown, not permission to substitute another pocket. The viewer requests the recorded `AF-...-F...-model_v...` source model explicitly, caches by model rather than accession, preserves pLDDT coloring, and never silently falls back to a different release. If that version is unavailable, a message replaces the structure. This does not verify changes introduced during receptor preparation.

Protein profile has its own search box to the left of Target AA. Search loaded proteins by UniProt accession, gene symbol, UniProt entry name or TAIR/Araport ID. Up to 20 suggestions include annotation identifiers; choose a UniProt suggestion or press Enter/click the arrow for a unique match. Ambiguous searches require choosing a protein rather than opening an arbitrary match. Search includes proteins outside Explorer's filters and proteins missing the current target-AA result, without changing Explorer search, target AA or ranking score.

The Protein profile heading also links its UniProt accession to UniProt. The **i** button to the right of the annotation identifiers opens the same TAIR gene-description dialog for the displayed protein. Within the dialog, available Other symbols appear beside the main gene symbol in each gene’s heading, rather than as a separate field below. The main symbol and repeated aliases are omitted from Other symbols (case-insensitive whole-symbol matching); the label is hidden if no alternatives remain.

In Explorer, Compare AAs and Top-hit overlap, clicking a protein accession opens UniProt in a new tab. The **i** button opens a gene-description dialog, and the separate **→** button opens the app’s Protein profile tab. TAIR locus IDs are matched from the result’s `tair_id` and the UniProt annotation’s Araport/gene-name identifiers, normalizing case and transcript suffixes such as `.1` to the gene-level ID. Multiple mapped loci are displayed separately; unmatched IDs and missing description fields are not fabricated.

Keep `annotations/arabidopsis/At_custom_description_file.csv.gz` in the published site. It is loaded only on the first description request and cached in memory; a missing annotation file does not stop docking results from loading. The CSV must contain `gene_id` and at least one of `Short_description`, `Gene_description` or `Computational_description`. Quoted commas, escaped quotes and multiline fields are supported, and `NA` values are treated as missing. All available annotation fields are displayed without a collapsible section. Notes appear before Protein families, and Gene model type appears before RefSeq IDs. Annotation text is displayed as text, not executed as HTML. The source file is not modified.

The Top-hit proteins table’s **Competitive AAs** column shows **x/20**, counting membership across all 20 canonical AA top-hit lists, regardless of which AAs are selected for overlap. For example, `8/20` means a protein is a top hit for eight AAs, even when only ALA and LEU are selected. ## Score histogram

Both histogram views apply the P2Rank probability and pocket mean pLDDT filters before choosing one best successful pocket per protein for the selected AA and score. All proteins ignores search, top-tier, and specificity filters. Table-filtered list additionally uses the matching rows from all table pages, retaining each protein's best matching pocket. Quartiles and the median follow the histogram population. Bins are colored by score tier: Top 1% (dark purple), 1–5% (blue), 5–10% (gold), and outside Top 10% (pale purple). Bins crossing a cutoff use stacked color segments based on actual protein counts. Cutoffs are calculated among all proteins passing the two confidence filters, so they update with those thresholds but stay fixed between the two histogram views. Each cutoff is the score of the last protein inside that confidence-filtered rank-percentile tier. Histogram membership uses the same QC-qualified ranks as Explorer. Tied scores are ordered by UniProt ID and can fall on both sides of a rank boundary; colors therefore use protein ranks, not score alone. The score axis includes the confidence-filtered population's range in the filtered view.

## Pose electrostatics in Explorer

The sortable **qφ (kT)** column beside Score reads the optional `At_results/L/pose_electrostatics/electrostatics_<aa>.tsv.gz` files. Data files and downloads retain the machine-readable field name `qphi_kT`. It reports the selected AA's **Vina MODEL 1 in that row's pocket**, regardless of the selected Ranking score or the viewer's manual pose selection. It may therefore describe a different pose from the saved SFCT/Combined-selected pose. Both Best pocket and All pockets modes use the exact displayed `pocket_id`; qφ never selects a different pocket. The header and hover text identify the pose and units.

The pipeline defines `qphi_kT = sum_i (q_i/e) * [phi_receptor(r_i)/(kT/e)]`, including ligand hydrogens, using its exported AM1-BCC charge model. Values are in **kT**, unlike the pocket cloud's potential in **kT/e**. Negative qφ is favorable and positive qφ is unfavorable in the fixed receptor field; near zero can reflect weak or canceling contributions. Positive receptor potential favors the negatively charged carboxylate group, while negative receptor potential favors the positively charged ammonium group; both favorable arrangements contribute negatively to qφ. The total sums all ligand atoms, not either head group separately, and is **not binding free energy or a desolvation-corrected score**. This column is additional context only: existing docking scores, best-pocket selection, ranks, percentiles, selectivity, GO, QC, and the 3D viewer are unchanged. Clicking the header first sorts ascending (more negative first); missing values stay last in either direction.

Loading is asynchronous and independent of the core atlas/structure. Explorer shares the compressed electrostatics manifest with the viewer but does not fetch the pocket summary, point clouds, or ligand-coordinate tables. It verifies the exact current compact L manifest against the electrostatics bundle, matches its pocket-export hash to each row's provenance, and validates the selected AA's compressed pose-file checksum, headers, row count, unique pocket IDs, units and Vina pose identity. Only the selected AA table is requested, with a two-table cache. L values are never substituted for D or legacy IDs. Publish the pose files with their matching manifest; the compressed-byte checksum/HTTPS hosting requirements described below also apply here.

Only `status = success` with a finite `qphi_kT` is displayed. Failed, missing, clashing, mismatched, or blank values remain **—**, with an explanation on hover; an actual zero remains numeric zero. Optional-data errors do not remove docking rows or block the app, and failed downloads offer **Retry qφ (kT)**. CSV/TSV downloads wait for the selected-AA table to finish loading and include the entire filtered list, not just the current page. They append `qphi_kT` (full exported precision), `qphi_status`, `qphi_vina_pose`, and `qphi_error`; unavailable values are blank with explicit status. No source data files are modified.

## External structure viewer

The protein profile loads only the currently selected AlphaFold model; structure files are not bundled with the app. It uses Mol* 5.11.0 from jsDelivr (MIT license) and AlphaFold DB structure data (CC BY 4.0). The app links visibly to both services. An internet connection is required for this panel.

The **Protein: Cartoon / Surface** buttons switch the receptor between an explicit **polymer-cartoon** (default) and a **molecular-surface** at 45% opacity. **Color** independently offers **pLDDT** (default), **Residue charge**, **Residue polarity**, and **None** (uniform gray). Charge coloring is a qualitative residue-name classification: ASP/GLU red, LYS/ARG blue, HIS ochre (protonation-dependent), and other/unknown residues gray. It is not calculated electrostatic potential or formal/partial charge assignment, and does not model pH, local pKa shifts or terminal charges. No scores, ranks or QC calculations change.

**Residue polarity** uses two muted colors plus gray for unclassified residues. Following the canonical-residue grouping in [ProDy’s polar/hydrophobic selections](https://www.bahargroup.org/prody/manual/reference/atomic/flags.html#protein), polar residues (ARG, ASN, ASP, CYS, GLN, GLU, GLY, HIS, LYS, SER, THR, TYR) are blue, and nonpolar residues (ALA, ILE, LEU, MET, PHE, PRO, TRP, VAL) are tan. Unknown/modified residues stay gray. Charged residues belong to the polar group. This explicit convention includes GLY/CYS/TYR as polar; classifications can differ, so it is not a quantitative hydropathy scale, local polarity calculation, hydrogen-bond prediction or electrostatic potential. Legend tooltips list both groups. The same receptor-only coloring path serves cartoon and surface without downloads or geometry rebuilding; the green pocket override remains optional and sticks/ligand/cloud colors are unchanged.

**Green pocket override** (on by default) independently overpaints the selected pocket's chain/residue IDs on the cartoon and surface. Turn it off to reveal the chosen protein colors inside the pocket. **Show sticks** (off by default) controls only the additional green bond cylinders; hydrogens are hidden. Either option can be enabled without the other. Color and pocket layers are replaced, not accumulated; missing pockets remove only the pocket override while retaining the selected color scheme. Newly created surfaces inherit the current color and override settings. The surface is computed on first use and cached for the loaded model; style/color/sticks/highlight controls preserve the camera, coordinates and ligand/cloud layers without new downloads. Preferences persist when switching proteins within the app session. The ligand stays element-colored ball-and-stick; P2Rank point colors have a separate control. The protein surface comes from receptor atoms, not the P2Rank cloud.

**P2Rank point clouds:** Show pocket cloud (on by default) reads the optional `At_results/pocket_points.tsv.gz`. Columns are exactly `pocket_id` and `points`, with semicolon-separated `x,y,z` triplets. IDs must reference the same `At_results/L/pockets.tsv.gz` export; D and legacy ID namespaces are not substituted. Publish the matching point table whenever pocket IDs change. The coordinate-only table does not independently identify its receptor model or export version. Its first download is about 21 MB, starts only on profile demand, and runs outside the Mol* update queue so it does not block pocket/ligand switching. One shared table is cached; point arrays are parsed only for the selected pocket. Failed downloads can be retried by toggling the checkbox.

Every exported point is rendered at its supplied coordinate as a small sphere (gold by default), radius 0.55 Å and opacity 30%. The spheres form a **point cloud**, not a smoothed/interpolated mesh or experimental cavity volume. A temporary in-memory PDB carries uniquely named pseudoatoms into Mol*; no point bonds are drawn and no positions are shifted, padded or sampled away. The actual exported count is displayed, with the original `sas_points` count separately when different. Missing/invalid point rows leave the protein, pocket sticks and ligand available. Pocket changes, hidden clouds, failed builds and stale requests remove the cloud's own layer only. Clouds never enter scoring, quality filtering, control-site recovery or other statistics.

**Pocket-point color: Gold / Electrostatic potential.** The optional electrostatics overlay uses the existing v1 export in `At_results/electrostatics`: `manifest.json.gz`, `pocket_summary.tsv.gz`, and `points_<model>.tsv.gz`. It does not use pose/ligand energy tables or require APBS grids in the browser. The fixed manifest scale is −5 / 0 / +5 kT/e with red / white / blue (`#d73027`, `#ffffff`, `#4575b4`), following the [APBS visualization convention](https://apbs.readthedocs.io/en/stable/using/examples/visualization-pymol.html). Colors are interpolated and saturated at the endpoints; numerical potentials are not clipped. This shows **receptor potential at P2Rank sample points**, not binding energy, affinity, experimental evidence, or a newly calculated protein surface.

The shared manifest and summary load only on first demand. Per-model potentials are fetched only for the selected protein, with a two-file LRU cache; no other protein's potentials are preloaded. A custom Mol* color theme updates the existing point representation only, using unique pseudoatom IDs to preserve correspondence if Mol* reorders atoms. Protein/cartoon/surface colors, green sticks/override, ligand, point size/opacity, and camera are untouched. Background fetches do not occupy the structure-update queue; stale responses cannot recolor a different pocket or override a subsequent Gold selection.

Validation requires the exact versioned model and pocket rank, a successful summary status, matching point counts, contiguous zero-based `point_index`, and the summary's coordinate fingerprint (SHA-256 of `x,y,z;x,y,z;...`, fixed three decimals, `-0.000` normalized to `0.000`, no newline). It also verifies compressed summary/point-file SHA-256 checksums. The electrostatics bundle's compact-manifest checksum binds the local L manifest to this export, and its `pockets.sha256` must match the selected score row's pocket provenance. This bridges the two export conventions: electrostatics hashes compressed gzip bytes; compact pocket metadata hashes decompressed TSV text. The model ID and sampled coordinates are checked, but the prepared PQR receptor is not independently compared with the downloaded AlphaFold structure.

Failed/missing/mismatched calculations remain explicitly unavailable and gray, never zero. Blank individual potential samples are gray; valid zero is white. Use **Retry potential** for transient failures or switch to Gold. Checksum validation requires a secure context (HTTPS or localhost). Serve `.gz` exports as files, **without `Content-Encoding: gzip`**, so the browser can verify their original compressed bytes before decompression. If files are regenerated or re-compressed, regenerate/publish their matching manifest checksums too. The existing v1 files need no conversion; scores, ranks and QC calculations are unchanged.

**Docked ligand overlay:** Show ligand (on by default) reads `At_results/L/aa_positions/positions_<aa>.tsv.gz` on demand. These optional three-column tables (`pocket_id`, `pose_id`, `positions`) contain semicolon-separated `element:x,y,z` atoms. Each pocket exports Vina MODEL 1 and the saved SFCT/Combined-selected pose, with only one row when both identify MODEL 1. `pose_id` is the actual one-based Vina MODEL number; the saved score field `sfct_best_pose` is zero-based, so the corresponding `pose_id` is `sfct_best_pose + 1`. Coordinate rows are unique by **pocket_id + pose_id**, not pocket ID alone. Export the saved selection without recalculating it. IDs must come from the same compact L bundle as `pockets.tsv.gz`; export/publish these together whenever pocket IDs change. The older two-column coordinate format is not supported by the current viewer.

The **Ligand pose** selector offers:

- **Auto (follow Value type)**, the default: Vina uses MODEL 1; SFCT and both Combined variants use the saved SFCT/Combined-selected pose. The profile's normalization checkbox does not change pose selection, and percentile options follow their underlying Combined score.
- **Vina-best (MODEL 1)**: display the exported Vina-best pose independently of Value type.
- **Saved SFCT/Combined**: display the saved selection independently of Value type. The shown MODEL number updates for the selected AA and pocket; this is a selection rule, not a fixed model number across proteins.

The selected model and whether it is automatic/manual are labeled below the viewer, with a note when a manual choice differs from Value type's pose. Manual changes update only the ligand layer, without resetting the camera or rebuilding the protein/cloud. They do **not** change table scores, plots, rankings, GO or Control QC, or calculate new pose scores. SFCT and Combined 50% still describe/reweight the saved Combined-80%-selected pose; the coordinate files contain no additional pose-specific scores. Explorer's **qφ (kT) remains specific to Vina MODEL 1** regardless of the displayed pose.

Only two requested AA coordinate tables are cached, atoms are parsed for the selected pocket/pose, and no coordinates are added to the main statistical dataset. The compact loader retains bundle provenance to prevent accidental joins to D or legacy IDs. Missing/failed selected scores, invalid pose indices, absent coordinates and malformed atoms leave the receptor visible with a ligand-specific unavailable message; no other pose, AA or pocket is substituted. Toggle Show ligand off/on to retry a failed download.

The ligand is built as an in-memory PDB and shown as element-colored ball-and-stick, with hydrogens hidden. Original coordinates are preserved. Mol* infers bonds for display, since the export contains no bond topology, bond orders, formal charges or canonical atom names. The version-pinned receptor must share the docking coordinate frame; receptor-preparation transformations cannot be recovered from these coordinate-only tables. D-AA overlays are not inferred from L coordinates. Displayed poses are docking predictions, not experimental binding sites or proof of binding.

## Experimental positive-control QC

The individual-controls table is always expanded and uses the same control set as the recovery plot. With the default eligible denominator it shows only controls with usable scores for all four metrics under the selected AA, pocket mode and QC settings; All known controls includes missing, unmatched and QC-excluded controls, consistently with the plot denominator. A visible count reports the displayed subset. Table downloads use that same subset. The table supports clickable column sorting; clicking the active header reverses direction. File order is preserved until a sort is chosen, and the chosen sort persists across QC filter/mode changes. Numeric percentiles and overlap fractions are sorted numerically, with missing values last in either direction. Analyzed-site coverage has separate Vina/SFCT/Combined sort buttons; Control-site match sorts by matched residue-overlap fraction. Sorting changes only table/export order, not QC calculations or curves. The separate **PDB ID** column links to each experimental structure's RCSB PDB entry in a new tab. Existing UniProt links, gene descriptions and protein-profile arrows remain unchanged; TSV downloads follow the current table order.

The independent **Control QC** tab loads `annotations/arabidopsis/strict_WT_single_protein_AA_controls.tsv` on demand. The quoted TSV is parsed without modifying the file. Eligible canonical AA × UniProt pairs are counted once; duplicate pairs trigger a clear error instead of inflating recovery. A missing or malformed control file only disables this panel and offers Retry, not the rest of the app.

The recovery plot compares **Vina, SFCT, Combined 80% and Combined 50%**, with X = top proteome percentile and Y = cumulative percent of known AA–protein controls recovered, plus the ideal random-reference diagonal `y = x`. The compact summary reports Top 1%, 5% and 10% with counts and percentages. Control AA selection defaults to all controls and is independent of the macro-analysis AA/score/observation unit. The Control QC tab’s own P2Rank (default 0.7) and pLDDT (default 90) filters apply before choosing each metric's best successful, finite pocket and defining the full-proteome reference separately within each AA. **Pocket selection** defaults to **Best-scoring pocket**, which uses that best pocket for the control. **Control-matched pocket** instead uses the predicted pocket with maximum experimental-residue overlap, even when another pocket scores better. The mode updates curves, Top 1%/5%/10% summaries, analyzed-site coverage, audit details and downloads. Combined 80% uses the supplied column; Combined 50% reweights the saved pose’s origin/SFCT values. Percentiles follow the existing `100 * (rank - 1) / (N - 1)` convention (singleton 0, UniProt tie-break).

By default all four curves use the same controls with eligible ranks for all four scores. Switch **Recovery denominator** to **All known controls** to include missing/failed/QC-excluded controls in the denominator without inventing scores or percentiles. Each score recovers its own available controls in that view, and curves may not reach 100%; the diagonal is not adjusted for missing coverage. The panel reports coverage, and an always-visible, configuration-filtered audit table plus **Download control QC TSV** exposes score-specific populations, scores, pockets, percentiles, tier membership, missingness, residue overlap and all settings. This is descriptive, conditional QC, not proof of binding or an independent validation cohort.

**Control-site matching is a residue-overlap approximation, not a pocket-ID lookup.** It compares the table's confirmed `UniProt_contact_positions` (`UniProt_mapping_status = contact_overlap`) with chain-A residues of matching AlphaFold F1 models, not PDB author numbering. The geometry match is the pocket with the most mapped experimental residues; ties use lower P2Rank rank followed by model/pocket/residue identity, never docking score. It must contain at least 50% of the mapped experimental residues by default; choose any-residue, 25%, 75% or 100% as alternatives. Matching happens before target-AA score availability or quality filtering. All four metrics then use the same geometry-matched pocket, with no fallback to another pocket if its target-AA result is missing, non-finite or fails QC. Pockets are pooled across all loaded AA results independently of docking score, deduplicating identical pocket/model/residue records. Different pockets are never unioned into a synthetic site. Unsupported numbering, missing site positions and absent usable pockets are unknown.

Matched-pocket percentiles use the unchanged per-AA, per-metric best-pocket proteome as reference: `100 * count(other proteins preceding the matched score) / (N - 1)`, with UniProt tie-breaking and singleton 0. The control's own best score is excluded; other controls are not replaced simultaneously. This preserves a full-proteome reference rather than ranking only annotated controls or treating every pocket as a protein. Control-matched mode is known-site-conditioned scoring, not blind pipeline validation; the random diagonal is illustrative.

**Analyzed-pocket site recovery** uses the same pockets as the QC scores, separately for Vina, SFCT, Combined 80% and Combined 50%. Its denominator is controls with a usable QC-passing score and comparable site residues for that metric's analyzed pocket, independently of the curve denominator. Evaluable / known reports coverage; missing/unmatched controls are excluded explicitly, never scored as zero overlap. In matched mode the overlap criterion is enforced during selection, so 100% among evaluable matches is expected, not an independent site-recovery result. TSV exports include the mode, threshold, match status, chosen pockets, metric-specific scores/percentiles/site coverage, counts and reference convention. Only pockets retained in successful docking result rows are available, so this is not full P2Rank sensitivity or a 3D ligand-to-pocket distance benchmark. Details are in Methods above the GO section.
